# Floating dock modernization

## Debt inventory

Baseline `819f8a055763a303e6172812cd849c10d92074b3` retained a static slotted FloatingDock and an exported useDraggable composable, but no Patterns/FloatingDock story. All seven legacy drag cases navigated to absent Patterns content. Three original failures were rerun unchanged in cloud and reproduced. Those tests assumed nonexistent header, control and tab classes; conditional assertions and fixed sleeps could not certify retained behavior.

The original composable only listened to mouse input, treated viewport coordinates as transforms (adding layout offsets to movement), ignored HTMLElement and non-body selector bounds, and did not constrain inertia. Dragging had no handle isolation or touch cancellation support. These were implementation defects as well as fixture debt.

## Implemented behavior

FloatingDock keeps its existing default variants, positioning, size, slots and non-draggable behavior. Opt into `draggable`, `bounds` (viewport `'body'`, selector or HTMLElement), and optional `inertia`. The handle slot customizes a real focusable handle. Only that handle starts pointer movement; slotted buttons/links remain usable. Focus the handle and use arrow keys for 10px steps, or Shift+arrow for 50px steps. The same bounds apply to keyboard input.

The exported composable uses Pointer Events and capture, ignores secondary contacts/buttons, tracks translation relative to the existing layout transform, resolves nearest ancestor bounds before global selectors, and clamps movement and the momentum destination. Cancellation, lost capture, disable and unmount stop dragging without launching inertia; interrupting movement stops the prior tween. Inertia respects reduced motion. Translation state remains plain x/y data rather than being mutated by GSAP's option normalization.

The new native Histoire story composes the real dock, real Button and Vue state. Panel selection, action count and reset are functional examples of slotted content, not fabricated application data. Tabs support arrow/Home/End navigation and roving focus. Light/dark surfaces, gold dark accent, typography and radii reuse the opt-in LUM contract and actual bundled fonts. No global consumer theme override is added. This applies the saved design language; it does not claim new Paper review, human approval or original-canvas pixel parity.

Seven meaningful drag E2E cases replace the old hypothetical DOM assumptions. They measure pointer deltas, active cursor/shadow/pressed feedback, all four bounding edges, control and keyboard operation, rapid movement, selected panel/action persistence, geometry settling and capture cancellation. No conditional no-op pass, arbitrary sleep or removed behavioral assertion remains. The separate browser harness also dispatches real Chromium touch input, adds a second contact, cancels the gesture and activates a control afterward. Six responsive light/dark screenshots and overflow assertions cover 320/768/1440px. Unit tests cover coordinate, viewport/element bounds, keyboard, inertia and lifecycle regressions.

## Verification and scope

The original six Button cold-start cases, font verification and package boundary checks remain. The repeated cold-start gate now also runs the seven repaired drag cases. The full legacy diagnostic runs each of the five existing browser projects independently with two workers and the existing 240-second global/15-second test/5-second assertion deadlines. Its old three-failure stop is overridden with `--max-failures=0` solely to expose more failures; failures still fail the job and upload reports. No retries, snapshot acceptance, skipped tests, increased deadlines or blanket pass condition is introduced.

Full-suite results and remaining-test baseline comparisons are recorded separately in the diagnostic evidence and draft PR. Browser-only data and screenshots are generated in cloud. The original Paper canvas PNG and human approval remain unavailable; credential rotation/history review remains owner-only. Model ID and reasoning setting are unavailable in this session.

The related eight FloatingDock behavior cases now assert retained/implemented behavior rather than hypothetical Control Panel/System Status/minimize APIs. Position reset is exercised and must preserve selected panel/action state. The formerly conditional no-op timeline visual case now checks real keyboard handle focus; the three other dock visual cases target the actual rendered preview and panels. Their screenshot assertions remain active, and missing Linux baselines remain failures. No generated golden image is accepted. Generic Button/Simple Demo visual and navigation debt is reported separately.
