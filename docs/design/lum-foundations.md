# LUM foundations adoption — candidate v1

Paper: https://app.paper.design/file/01M5B3090WZG0DQBNMW4CGSVXV/p-1-0
Candidate dated 2026-10-19, not user-approved. The supplied exact computed styles, JSX and tokens informed composition; final leaf font/foreground corrections postdate the exports. This implements the content through Vue and Histoire's own navigation, search, variant and theme controls. It is not a pixel-parity or approval claim. The unprovided candidate PNG is not committed; reserve `screens/button-foundations-v1.png` for the coordinator's original export, without substituting a browser screenshot.

Reference files read through GitHub: LUM Brain `src/styles/design-tokens.ts` (blob e7e0c2362848c209914a5d9da2bcaa5657b663b8), `src/styles/fonts.ts`, `src/dashboard-shell-css/primitives.ts` and `shell-chrome.ts`. The latter two live directly under src, not src/styles. Only core neutral/status tokens are adopted; no owner, CRM or app data tokens are exported.

Import `synapseui/style.css` for library styles. Import `synapseui/lum.css` afterward and apply `data-synapse-theme="light|dark|system"` on an ancestor to opt in. Canonical variables map to legacy semantic names within that scope; no global LUM palette is imposed on consumers. The demo self-hosts the unmodified Geist and Geist Mono variable WOFF2 fonts from geist@1.4.2 under SIL OFL 1.1. Library consumers explicitly import `synapseui/fonts.css` to register those faces; neither core styles nor font registration overrides consumer element styles. Fallbacks remain for load failure/delay, and no font service request is introduced. See [font licensing and verified loading](typography.md). Numbers/code use Mono in the documentation. Theme selection/persistence belongs to the host; Histoire retains its built-in setting and storage fallback. Explicit story variants permit deterministic review independently of chrome theme.

The 30px heading, 16px subtitle, 32/24px desktop composition, 16px mobile inset, 6/8/10/12/16px radii, dark gold primary and themed on-accent foreground follow the handoff. Histoire keeps its own layout rather than receiving a duplicate 240px sidebar. Responsive preview is disabled only for this story so it follows the available container instead of clipping a fixed 720px canvas on phones.

Button keeps all historical variant names, sizes, `as`, `asChild`, icon slots, type and click API. Public `buttonVariants` now describes the Button actually exported. `md` stays 40px; documentation targets are at least 44px. Disabled/loading blocks native activation and captures canceled link navigation, including composed children. Native button type defaults to button; arbitrary custom elements must supply appropriate keyboard semantics. Slot content survives by default. Text warp and corner pulses are opt-in; reduced-motion CSS covers descendants and runtime checks skip their triggers. No ripple or imperative setLoading API existed in BaseButton; obsolete tests for those hypothetical APIs are replaced with actual behavior assertions. Other unit/E2E suites are retained. Loading uses aria-busy and retained visible text; supply meaningful text or aria-label for icon-only actions. Clipboard success follows resolution, with selectable-code fallback on failure.

Input retains model/change/focus/blur and exposed focus methods, adds aria-invalid, validates input event targets at runtime, and makes corner motion opt-in. Input/dialog/tooltip work beyond this foundations slice remains future work; existing stories are retained. Histoire owns search empty/error surfaces; no fake backend or duplicate search shell is added.
