# Button story cold-start diagnosis

The failure at `c114285e` was in the repaired Button coverage, separate from missing Patterns stories. Three independent hosted cold starts at the unchanged test head `102fe8db` reproduced it: [run 39345572966](https://github.com/goatcheese98/synapseui/actions/runs/39345572966), jobs 118377211683, 118377212040 and 118377212072 each had one first-case Primary visibility failure and five subsequent Button passes. Each used a fresh checkout, install, Histoire process and browser contexts, without retries.

A cloud fresh-start six-case run passed without throttling. Three additional cloud fresh starts under Chromium's 6× CPU throttling reproduced the first-case deadline failure. Navigation completed at about 1.8 seconds, the Button story module responded around 4.2–4.6 seconds, and the expected Primary content appeared after the five-second assertion budget. Captured page errors were empty. The diagnostic screenshots show the correct Main Variants fixture and Primary content by capture completion; they do not imply the content was present when the assertion expired. [Timing evidence](button-cold-start.json) explicitly distinguishes screenshot time from assertion time.

Histoire's Vue plugin mounts a separate app for each preview after route navigation. Its RenderStory implementation appends a target, calls `app.mount(target)` (which supplies `data-v-app`), then emits `ready`. Tests now identify the **Main Variants** grid item by its exact accessible link and wait for that preview's `.histoire-generic-render-story > [data-v-app]` mount. The subsequent exact-name Primary assertion still has its original five-second deadline. Button assertions are scoped to the rendered grid and use accessible button names, excluding Histoire's hidden collection mount and shell controls.

Three more throttled fresh starts with this mount wait passed the unchanged Primary assertion: preview mounts occurred around 10 seconds and content checks completed within the existing test deadline. [Ready screenshot](screens/button-cold-start-ready.png). All six existing cases and all fifteen expected variant labels remain: variants, sizes, interactions, classes, keyboard accessibility and mobile behavior. No retries, sleeps, skips, absent-content expectations, increased assertion/test deadlines or product changes are involved.

The dedicated `Button cold-start verification` workflow keeps three independent fresh jobs for these six cases. It retains traces on failure, screenshots and reports. The ordinary legacy diagnostic still runs all registered tests with its bounded failure cutoff; missing Patterns failures remain outside this correction. Hosted results for the final tested head are linked in the draft PR.

## Evidence limits

The original hosted artifact was obtained as a connector file reference, but the cloud download route returned proxy HTTP 403. A proposed recovery step to print its image into CI logs was rejected by automatic approval review as unnecessary artifact exposure and was removed before publication. The original screenshot/error-context file could not be inspected directly; its timeout and selector are confirmed by the original hosted logs, and the same failure was independently reproduced in all three hosted jobs and in captured cloud traces/screenshots. The original configuration recorded traces only on retry despite disabling retries; the dedicated cold-start jobs now retain traces on actual failure.
